# 학급관리 Android APK 프로젝트

- 자리교체의 자동 섞기, 배치 확정, 자리 이력, 학급 명렬 관리 기능 포함
- 출결: 교탁 시점 학생 자리 탭, 결석·지각·조퇴·결과와 질병·인정·미인정·기타 조합
- 기기 날짜 자동 적용, 과거 날짜 정정, 월별 집계, CSV·JSON 백업
- 사진 명렬: 촬영/선택 → 앱에 포함된 한국어 OCR 모델 → 번호·이름 수동 확인/수정 → 저장
- 학생 정보와 사진은 앱에서 외부 인터넷으로 전송하지 않음. 앱에 INTERNET 권한 없음
- 학급관리의 자리교체에서 확정한 배치와 명렬을 출결 화면으로 자동 전달 (출결은 기존 기록 유지)

## 빌드
GitHub Actions 'Build 학급관리 APK' 실행 결과 아티팩트에서 app-debug.apk 설치 파일을 받으세요.
Android Studio에서 class-manager-apk 폴더를 열고 Build > Build APK(s)로 빌드할 수도 있습니다.

## 중요
기존 웹앱의 로컬 저장소와 APK 앱 저장소는 달라서 자동 이전되지 않습니다.
자리교체·출결 백업(JSON)을 각각 불러오세요. 스마트폰 화면 잠금을 설정하고 학교 개인정보 규정을 지켜 주세요.
APK 내부 데이터는 PC와 자동 동기화되지 않습니다. 업데이트 또는 삭제 전 JSON을 백업하세요.
개발용 debug APK는 서명 키가 변경되면 기존 설치본에 업데이트할 수 없습니다.

### 기존 APK 사용자가 먼저 알아야 할 사항
기존 배포본은 개발용 디버그 키로 서명되어 새 디버그 APK의 서명과 일치하지 않을 수 있습니다. 이 경우 기존 앱에 직접 덮어쓸 수 없고 삭제하면 내부 기록이 삭제됩니다.
1. **기존 앱에서 자리교체 백업 JSON과 출결 전체 백업 JSON을 각각 저장하세요.**
2. 먼저 별도 패키지 `kr.jbmath.classmanager.preview`의 **'학급관리 테마 미리보기'** APK를 설치해 테마를 확인할 수 있습니다. 기존 학급관리 앱을 삭제할 필요 없습니다.
3. 실제 교체 시 JSON 두 개를 안전하게 보관한 뒤 기존 앱 제거 → 새 학급관리 앱 설치 → 기존 JSON 복원 순서로 진행하세요.
4. 파일을 안전한 승인 저장소에 보관하고 메신저·공개 저장소에 공유하지 마세요.

## v1.2.0 · 나이스(NEIS) 스타일 교시별 출결 입력
출결 관리 → 학생 자리(또는 명렬) 터치 → 출결 유형/구분 선택 → 교시 선택 → 필요 시 세부 사유 버튼 선택 → 저장.
교시 목록은 조회, 1~6교시, 종례 총 8개 시간입니다. 학교 학사일정에 따라 실사용 교시 확인이 필요합니다.

- **결석**: 조회부터 종례까지 8개 시간이 모두 자동 선택되고 개별 해제는 할 수 없습니다.
- **지각**: 마지막 미참여 교시 하나만 터치하면 조회부터 그 교시까지 모두 선택됩니다.
- **조퇴**: 처음 미참여 교시 하나를 터치하면 그 교시부터 종례까지 모두 선택됩니다.
- **결과**: 불참한 교시를 개별 터치해 복수 선택할 수 있습니다.
- **출석/미입력**: 미참여 교시가 없습니다.
- **출석인정 결석**의 세부 사유 버튼: 감염병 / 생리 / 교외체험학습 / 기타 직접 입력.
- **질병 결석·질병 조퇴**의 세부 사유 버튼: 감기 / 복통 / 두통 / 병원진료 / 기타 직접 입력.
- 선택한 교시(\`periods\`)와 세부 사유(\`detailReason\`)는 기존 출결 JSON의 날짜별 학생 레코드에 **추가 필드**로 저장됩니다. 기존 \`status\`, \`reason\`, \`memo\`, \`time\` 필드는 유지하므로 이전 출결 기록을 그대로 확인·정정할 수 있습니다.
- CSV에는 별도 세부 사유 열 및 조회~종례 8개 열을 포함하여 미참여 시간을 \`/\` 로 표시합니다. 이는 나이스 업로드용 공식 양식이 아닌 **보조 확인 자료**입니다.
- 출석인정 항목은 홈 및 일일 현황에서 별도로 집계해 일반 결석과 혼동하지 않도록 했습니다.

### 주의
나이스와 동일한 공식 처리 시스템이 아닙니다. 같은 날 여러 종류의 지각/조퇴/결과가 발생했다면 사선 표시와 최종 마감 유형은 학교 규정에 따라 별도 판단해야 하며 이 버전은 한 학생·한 날짜에 하나의 주 유형을 저장합니다.
출석인정은 학교장의 허가·학교 규정·해당 증빙 확인이 전제됩니다. 출결 세부 사유는 민감한 정보가 될 수 있으므로 꼭 필요한 범위만 입력하고 기기의 잠금을 유지하세요.

자동 검증: \`cd class-manager-apk && node --test tests/attendance-periods.test.cjs\`

## v1.3.0 — 과거 날짜 저장, 저장 마감, 일괄 삭제, 전체 통계

### 날짜 선택 오류 보완
- 출결 날짜를 사용자가 선택하면 앱 사용 세션 안에서 그 날짜를 기억합니다. 자리교체 이동이나 배치 동기화 때문에 출결 화면이 다시 로드되어도 이전에 선택했던 날짜로 복원됩니다.
- 앱을 완전히 새로 실행한 세션은 휴대폰의 오늘 날짜가 기본입니다.
- 학생 출결 편집창을 열 때 날짜를 고정하고, 저장은 반드시 편집창의 대상 날짜로 합니다.
- 날짜 표시줄에서 작업 날짜, 마감 여부, 기록 건수를 확인할 수 있습니다.

### 저장 마감/마감 해제
- 선택 날짜를 '저장 마감'하면 closedDates 영역에 날짜·시각을 기록하고 해당 날짜의 수정 및 미입력 학생 일괄 출석을 차단합니다.
- 마감 상태에서도 날짜 조회·통계·CSV·JSON 백업이 가능합니다.
- '마감 해제' 후 해당 날짜를 다시 수정할 수 있습니다.
- 이 마감은 학급관리 앱 내부 마감이며 나이스 공식 출결 마감이나 전송이 아닙니다.

### 출결 일괄 삭제
- '현재 선택 날짜', '기간 지정', '전체 날짜' 중에서 날짜 범위를 선택할 수 있습니다.
- 마감된 날짜는 기본 제외하고, '마감된 날짜도 포함'을 직접 선택했을 때만 함께 삭제합니다.
- 삭제 대상 날짜 수와 기록 수를 표시합니다. 최종 삭제 창에서 '삭제'를 직접 입력해야 실행됩니다.
- 학생 이름과 좌석배치는 그대로 유지합니다. 삭제된 출결은 JSON 백업에서만 복구 가능하므로 삭제 전 백업을 권장합니다.

### 전체 기록 및 통계
- '전체 기록·통계' 탭: 학생별(번호 오름차순) → 해당 학생의 날짜 과거순, 날짜별(과거순) → 각 날짜의 학생 번호 오름차순 전환.
- 기록 전체 또는 선택 월 필터. 출결 유형·세부 사유·미참여 교시 표시. 행을 누르면 해당 출결 날짜로 이동합니다.

### 기기·동기화 주의

자동 검사: node --test tests/*.test.cjs. 실기기 갤럭시에서의 전체 조작 검증은 별도 확인이 필요합니다.


## 동일 앱 덮어쓰기 업데이트 — 고정 서명 키 적용 (v1.3.1 빌드 설정)

### 중요한 결론
- Android는 **패키지 이름 + 동일 서명 인증서 + 더 높은 versionCode** 조건으로 앱을 기존 데이터 그대로 업데이트합니다.
- 지금까지 공개된 학급관리 1.0~1.3 APK는 GitHub Actions가 실행될 때마다 Android Debug 개인키를 새로 만들었습니다. 이 파일들은 인증서 SHA-256 지문이 달라 서로 덮어쓸 수 없습니다.
- **APK 안에는 공개 서명 인증서만 있습니다. 원래 개인키는 APK에서 추출할 수 없습니다.** 최초 debug APK를 생성한 일회용 GitHub Actions 작업 공간의 keystore 파일도 기존에 아티팩트로 보관하지 않았습니다.
- 따라서 원래 keystore(.jks 또는 debug.keystore) 원본과 비밀번호를 갖고 있지 않으면 기존 설치본을 바로 업데이트할 수 없습니다. 이 제한을 앱 코드로 우회하지 않습니다.

### 코드에 반영한 보호조치
1. Android release 빌드에는 CI에서 원본 keystore를 암호화된 GitHub Repository Secrets로 제공해야 합니다.
2. 빌드 전에 **기존 APK의 SHA-256 서명 인증서 지문**과 제공된 keystore 인증서를 대조합니다. 서로 다르면 빌드를 즉시 중단합니다.
3. release APK 빌드 후 동일 인증서 및 패키지명 `kr.jbmath.classmanager`을 다시 검증한 뒤에만 `ClassManager-SIGNED-UPDATE` 아티팩트로 제공합니다.
4. 임시 Debug APK는 **업데이트 설치 파일로 공개하지 않습니다.** 미리보기는 별도 패키지명 `kr.jbmath.classmanager.preview`으로만 제공합니다.
5. 공개 GitHub 저장소에 개인키 파일을 커밋하지 않도록 `.gitignore`를 추가했습니다.

### 원본 keystore가 있을 때 (Windows)
- JDK, GitHub CLI(gh) 설치 후 `gh auth login`을 실행합니다.
- 이전에 휴대폰에 설치한 **그 APK 파일**과 **당시 사용한 실제 keystore(.jks/debug.keystore)**, 키 alias를 준비합니다. Android Studio에서 로컬 빌드했다면 `C:\Users\<사용자>\.android\debug.keystore`일 수 있습니다.
- PowerShell에서 스크립트 실행: 
  `./scripts/configure-original-signing.ps1 -ExistingApk "C:\경로\기존학급관리.apk" -OriginalKeystore "C:\경로\원본.jks" -KeyAlias "androiddebugkey"`
- 스크립트가 APK와 키의 인증서 지문을 비교한 뒤 일치할 때만 **YES** 확인을 받아 GitHub Secrets를 설정합니다. 비밀번호/키를 GitHub 소스 코드에 기록하지 않습니다.
- `Actions → 학급관리 APK 검사 및 기존 키로 업데이트 빌드 → Run workflow → feature/class-manager-apk-20261107 → build_signed_update: true`로 실행합니다. 결과 `ClassManager-SIGNED-UPDATE`의 APK만 앱 업데이트에 사용합니다.

필수 저장소 Secrets: `CM_SIGNING_KEYSTORE_BASE64`, `CM_SIGNING_STORE_PASSWORD`, `CM_SIGNING_KEY_ALIAS`, `CM_SIGNING_KEY_PASSWORD`, `CM_SIGNING_EXPECTED_SHA256`. 필요한 경우 `CM_SIGNING_STORE_TYPE` (예: JKS/PKCS12)도 설정하세요.

### 원본 개인키가 없을 때
원래 설치된 앱에 대한 덮어쓰기 업데이트는 기술적으로 불가능합니다. **학생 명렬, 자리배치, 출결 전체 JSON을 먼저 백업**하고, 신규 **고정 서명 키로 새 버전을 최초 1회 설치**하는 전환 절차가 필요합니다. 새로운 keystore를 만든 뒤 위와 동일하게 Repository Secrets에 보관하면 이후에는 같은 키로 서명하고 versionCode를 올려 기존 데이터 보존 업데이트가 가능합니다.

### 신규 장기 서명 키로 최초 1회 전환하기 (원본 키 분실 시)
기존 Debug APK의 원본 키가 남아 있지 않다면, 앱을 기존 설치본 위에 직접 업데이트할 수 없습니다. 기존 앱에서 학급 명단·자리배치 및 출결 전체 JSON을 반드시 백업한 뒤 신규 서명 키를 등록하는 전환이 필요합니다.

원본 키를 찾을 수 없는 사용자를 위한 Windows PowerShell 스크립트를 추가했습니다.

`scripts/create-longterm-signing.ps1`

이 스크립트는 **사용자 자신의 PC**에서 신규 장기 키를 만들고, 사용자가 'MIGRATE' 및 'YES'를 직접 입력한 후에만 GitHub Actions 암호화된 Secrets에 등록합니다. **원본 키를 복원하거나 기존 APK 서명을 일치시키지는 않습니다.** 신규 키를 쓰는 APK는 기존 앱을 JSON 백업 후 제거하고 새로 설치해야 하지만, 이후 설치본에는 동일 키를 재사용해 업데이트할 수 있습니다.

GitHub Actions의 정식 서명 빌드 번호는 `10000 + GITHUB_RUN_NUMBER`로 자동 증가시키고, 패키지 이름과 인증서 및 버전 번호를 확인한 후 아티팩트를 제공합니다. 단, 기존 앱에 서명한 개인키가 있어야 기존 앱의 데이터가 그대로 유지되는 업데이트입니다.

**주의:** 이전 사용자가 설치한 기존 APK의 개인키가 보관되어 있는지 현재 확인되지 않았습니다. 아직 호환 가능한 정식 업데이트 APK가 만들어진 것은 아닙니다.

## v1.4.0 · 학생별 교외체험학습 누적 사용일수 및 기록 지우기

학생의 좌석 또는 명렬에서 **출결 입력창**을 열면 상단에 `교외체험학습 누적 사용일수`가 표시됩니다.

- 이번 학년도 3월 1일부터 **오늘까지** 해당 학생 번호의 **출석인정 결석 + 세부 사유 ‘교외체험학습’**으로 저장된 날짜를 중복 없이 합산합니다.
- 실제 저장된 날짜 목록도 보여줍니다. 아직 저장하지 않은 선택 내용으로 누적일수가 달라질 때는 ‘저장하면 N일’로 미리 안내합니다.
- 다른 출석인정 사유, 질병결석, 미래의 출결 기록, 이전 학년도 날짜는 집계에서 제외합니다.
- 결석을 수정하거나 삭제하면 별도 수기 수정 없이 누적일수도 자동으로 변경됩니다.
- **이 숫자는 앱에 저장된 출결 기록의 합계일 뿐, 학교의 공식 승인일수·잔여 허용일수를 나타내지 않습니다.** 해당 학년도, 승인 여부, 초과일수, 휴업일 및 학교 규정은 별도로 확인하세요.
- 현재 저장 구조는 학급 내 **학생 번호 기준**입니다. 학급이나 학년이 바뀌어 번호가 재사용될 때는 이전 자료를 별도로 백업해 분리 관리하세요.

`이 학생·이 날짜 기록 깨끗이 지우기` 버튼은 이미 저장된 출결 항목이 있을 때만 표시됩니다. 확인창을 거쳐 **선택한 학생의 해당 날짜 출결**만 삭제해 `미입력` 상태로 되돌립니다. 기존 학생 정보, 자리배치, 다른 학생·날짜의 출결은 보존됩니다. 마지막 기록 삭제 시 비어 있는 날짜 자체도 정리됩니다. 마감된 날짜는 마감 해제 전까지 삭제할 수 없습니다.

수정 사항은 Android APK와 통계 모듈에 공통 적용됩니다. 기존 고정 서명 APK 사용자는 같은 키로 `build_signed_update=true`를 켜서 빌드한 **정식 APK를 기존 앱 위에 덮어쓰기 설치**할 수 있습니다. 앱 제거는 필요하지 않으며, 업데이트 전에 전체 출결·자리배치 JSON 백업을 권장합니다.

테스트: `node --test tests/*.test.cjs`.
