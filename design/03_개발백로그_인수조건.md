## 인수 테스트 시나리오

### A. 회신·취합
1. 관리자 계정으로 40명 대상 '연수 희망 조사' 생성.
2. 3명이 회신하고 1명은 수정 제출 → 제출자 3명, 미회신 37명.
3. 다른 교직원이 링크를 통해 요청자 결과 상세 URL을 열면 접근 거부.
4. 마감 후 다시 제출하면 저장하지 않으며 사유 표시.
5. XLSX 다운로드를 열어 응답 행·선택값·한글이 맞는지 확인.

### B. 수행평가
1. 만점 20점, 기준 4개, 0.5점 단위 평가 생성.
2. 학생 30명 명단 가져와 29명 채점, 1명 '미채점'.
3. 미채점은 0점으로 잘못 변환되지 않아야 함.
4. 기준 변경 후 기존 점수 재계산 여부를 묻고 변경 이력 남김.
5. 인터넷 차단 중 정상 사용 및 암호화 백업 생성·복원.

### C. 회의·협의회
1. 안건 3개 및 참석 대상 8명으로 회의 생성.
2. 안건 1개 보류, 2개 결정; 결정사항에 담당자·기한 설정.
3. 담당자 할 일에서 완료 클릭 → 회의 상세에 완료 반영.
4. 회의록 수정 버전 및 기존 버전 비교 가능.

### D. 학기말 기록 검토
1. 이름 없는 샘플 10건 업로드, 동일 문구 2건 탐지.
2. 길이 제한은 설정과 계산 방식(글자·UTF-8 바이트) 표시.
3. 지침 출처가 없는 검토 규칙은 '근거 미확인' 경고.
4. 원문을 자동 수정하지 않으며, 교사가 직접 수락해야 함.
5. 개발자도구 네트워크 탭에서 학생 원문 전송이 없음을 확인.

### E. 연수·참석
1. 정원 20명, 신청자 22명 → 대기 2명 처리.
2. 신청 취소 시 대기 승격은 정책대로 승인/자동 여부 표시.
3. QR 중복 체크인 시 중복 방지; 담당자 수동 정정은 이력 기록.
4. 내부 참석명부를 공식 연수 이수증으로 오인하지 않도록 표시.

### F. 업무 인수인계
1. 업무카드 5건에서 진행중 2건, 완료 3건 작성.
2. 인계자료 패키지 생성 시 미결 항목·기한·담당자 표시.
3. 인수자 확인 전·후 상태 비교 가능.
4. 텍스트에서 비밀번호/비밀키처럼 보이는 값에 경고 표시.

### G. 공문·제출서류
1. 물품 품의 기본 서식으로 금액 불일치·누락 첨부 발견.
2. 스캔 PDF가 지원되지 않으면 '검사 불가'로 표시.
3. 학교마다 다른 붙임 기준을 수정/저장할 수 있음.
4. 출처·버전 없이 특정 조건을 법적 의무로 단정하지 않음.

## 첫 개발 요청문 (복사하여 Claude/Codex 전달)

> 첨부한 01_종합_개발명세서.md와 02_데이터모델.json에 따라 JB School 프로젝트를 새 작업 디렉터리에서 구현해줘. 기존 학교업무 브리핑/품의꾸러미/JB WebApps 원본은 수정하지 말고 별도 보존해. 먼저 CORE-01~04, RESP-01~04를 더미 사용자 40명으로 완성하고, 기능 테스트/접근 권한 테스트/XLSX 출력 테스트를 실행해. 인증·서버 측 접근통제가 완성되지 않으면 정식 배포하지 말고 로컬 데모로만 실행해. 각 컴포넌트에 접근성·에러 처리·완료 보관함을 포함하고 README에 실행 방법과 검증되지 않은 항목을 명시해. 이후 RECORD-01~03과 GRADE-01~03은 별도의 완전 오프라인 로컬 도구로 구현하되 실제 학생 개인정보는 테스트에 사용하지 마.
