# 공동 회신 운영형 API 초안 — 미구현

> 이 문서는 단계 2의 서버 구현 계약입니다. 현재 `src`의 로컬 데모 코드에는 실제 API 요청이 전혀 없습니다.

## 인증·권한

- 기관 승인 인증 후 HttpOnly, Secure, SameSite 세션 쿠키 기반 접근을 우선 검토.
- CSRF 방어, 요청별 권한 확인, 속도 제한, 로그 마스킹.
- 역할: `org_admin`, `campaign_owner`, `target_respondent`, `summary_reader`.
- 모든 호출에 `org_id`로 테넌트 격리, 서버에서 유효 로그인 사용자 확인.
- 관리자도 모든 답변을 무조건 열람하지 못하게 하고 업무 목적별 열람 범위 설정.

## 초기 엔드포인트 제안

| 방식 | 경로 | 주체 | 동작 |
|---|---|---|---|
| GET | `/api/v1/me` | 로그인 사용자 | 나의 역할/소속 |
| GET | `/api/v1/campaigns` | 소유자/대상자 | 열람 권한이 있는 요청 목록 |
| POST | `/api/v1/campaigns` | 작성 권한자 | 새 조사 생성(초안) |
| PATCH | `/api/v1/campaigns/:id` | 소유자 | 문항/마감 수정, revision 증가 |
| POST | `/api/v1/campaigns/:id/publish` | 소유자 | 배포 상태 변경 |
| GET | `/api/v1/campaigns/:id/my-form` | 대상자 | 본인에게 허용된 문항 |
| PUT | `/api/v1/campaigns/:id/my-submission` | 대상자 | 본인 답변 제출/수정(멱등성 키) |
| GET | `/api/v1/campaigns/:id/summary` | 소유자 | 대상/유효 제출/미회신/질문별 집계 |
| GET | `/api/v1/campaigns/:id/export` | 소유자 | 권한 검사 뒤 CSV/XLSX 내보내기 |
| POST | `/api/v1/campaigns/:id/archive` | 소유자 | 완료 보관함으로 이동 |
| POST | `/api/v1/campaigns/:id/reopen` | 소유자 | 마감 재개, 이력 보존 |

## 중요 조건

- 본인 응답 제출에는 클라이언트가 전송한 `respondent_id`를 신뢰하지 않고 **인증된 서버 세션의 사용자**를 사용합니다.
- 질문은 `question_id`로 참조. 질문 변경은 이미 받은 답변과 충돌 검사/버전 관리 필수.
- 회신율 분모는 유효 대상자 집합, 분자는 유효 제출자 고유 수로 서버에서 집계.
- 미회신자 목록은 수신 경로 실제 전달 여부와 별개입니다. '안내 완료'는 발송 성공 로그가 있어야만 설정.
- 익명 조사 모드는 별도의 보안 설계 전까지 운영 API에서 제외.
- 학교 공식 알림 시스템 사용 승인을 받지 않으면, 리마인더는 **복사 가능한 문안 생성**까지만 구현.

## 운영 시나리오 테스트

1. 요청 작성자 A가 대상 40명 지정 후 공개.
2. 서로 다른 계정 3명이 본인 계정으로 회신.
3. 요약 결과 `전체 40/회신 3/미회신 37` 확인.
4. 해당 요청과 무관한 계정 B가 결과 조회 시 403.
5. 한 사람이 재제출하면 유효 회신 수는 그대로이며 수정 이력이 증가.
6. 마감 후 제출 409 / 담당자 재개 기록이 감사 로그에 남음.
7. 완료 보관함 이동 시 기본 목록 제외 / 권한 있는 담당자만 복원 가능.
