# JB School 보안·개인정보 기준

## 현재 버전 사용 제한

- **실제 교직원명·이메일·휴대전화·학생명·학번·학업성적·학생부 초안·비공개 공문을 입력하지 마세요.**
- 브라우저 `localStorage`는 평문 저장이며 암호화, 접근 제어, 감사 기록, 백업 보호를 제공하지 않습니다.
- URL 공유는 다중 사용자 회신 기능이 아닙니다. 서버에 제출되지 않으며, 복사/내려받기는 실제 발송·제출을 증명하지 않습니다.
- 서비스 워커 캐시는 프로그램의 정적 파일만 보관합니다. 업무 자료나 로컬 응답 JSON은 서비스 워커 캐시에 넣지 않습니다.
- 임의 외부 라이브러리·CDN 호출을 사용하지 않았습니다.

## 운영 배포 필수 게이트

- [ ] 학교 담당부서·개인정보 책임자의 운영 승인 및 데이터 분류.
- [ ] 기관 승인 로그인(SSO/OAuth 등), MFA/세션 정책 검토.
- [ ] 관리자·담당자·응답자·열람자 권한을 백엔드에서 단건별 검증.
- [ ] 정보 암호화(전송 및 저장), 인증 정보 비노출, 비밀키 서버 보관.
- [ ] 접근·변경 이력, 보존·파기, 백업·복원 정책 승인.
- [ ] 실제 발송 경로 승인 및 전달·실패·미확인 분리.
- [ ] 사용자별 변경 이력, 마감 후 수정 통제 및 중복 제출 제어.
- [ ] 문서 첨부가 생기는 경우 안전한 저장소·확장자/크기/악성파일 점검.
- [ ] 오류·감사 로그에 개인정보·답변 본문을 남기지 않는지 확인.
- [ ] 외부 공개 도메인·GitHub 저장소에 실제 학교 자료가 존재하지 않는지 점검.
- [ ] 사용자 테스트(20대~60대 교직원, Windows PC), 접근성, 승인된 브라우저 지원 확인.

## 학생 관련 오프라인 모듈

- 개인식별정보를 제거한 시연 데이터를 우선 사용.
- 평문 자동저장 기본 금지. 필요 시 기관 승인 보호 저장소 또는 사용자가 직접 관리하는 암호화 백업.
- 외부 API로 학생 초안을 전송하지 않는 구조를 유지.
- 학교생활기록 지침·학교 학업성적관리규정은 버전과 출처를 남기고, 자동 판정은 '교사 검토 권고'로만 제시.
- 인정점·결시·학생부 기재 가능 여부는 교사·승인 절차를 대체하지 않음.
